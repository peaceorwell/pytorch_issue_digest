# PyTorch Compiler Issue Digest - 2026-06-20

## 今日概览

- 标题关键词匹配 6 个 issue：open 4 个，closed 2 个。
- 今日主要风险信号是 open 的 `torch.compile`/Inductor 回归：ROCm `reduce-overhead` 训练疑似 silent degradation，以及 vLLM 2.13 Inductor `ShapeEnv` 兼容性崩溃。
- 主题集中在 Inductor runtime/cache、CUDA graphs on ROCm、dynamic shapes、floatx/Triton 架构支持，以及 fp16 reduction numerics。
- 有 2 个 silent-correctness 标签 issue：#187715 风险较高；#187721 已有 maintainer 评论倾向认为是 Inductor 默认数值策略，bug 证据偏弱。

## 重点关注

- [#187715 `torch.compile(mode='reduce-overhead')` silently degrades training on ROCm — `cudagraph_trees` has no HIP guard](https://github.com/pytorch/pytorch/issues/187715)
  - 关注原因: 涉及 ROCm 上 `torch.compile(mode='reduce-overhead')` 训练收敛变慢，带 `module: correctness (silent)`，潜在影响训练正确性。
  - 建议动作: 在 MI300X/ROCm 7.0 复现，并检查 `cudagraph_trees.py` 是否需要 HIP guard 或临时禁用该路径。

- [#187728 [vllm] [2.13 regression][Inductor] FxGraphCache._save_graph calls ShapeEnv.produce_guards_expression_with_source_info, missing on custom ShapeEnv](https://github.com/pytorch/pytorch/issues/187728)
  - 关注原因: 标记为 regression、bc-breaking、crash，vLLM standalone-compile engine init 失败，影响下游集成。
  - 建议动作: 对 `ShapeEnv` 新方法调用做兼容性判断，或与 vLLM 对齐 custom `ShapeEnv` API 迁移方案。

- [#187337 [inductor] model failed with torch._inductor.exc.InductorError: AssertionError: vr must not be None for symbol q3](https://github.com/pytorch/pytorch/issues/187337)
  - 关注原因: Dynamo benchmark + Inductor training 路径触发 dynamic shapes 相关 AssertionError，评论显示 Intel XPU Triton CI 也可能遇到类似问题。
  - 建议动作: 从 `jx_nest_base` benchmark 提取最小 repro，定位 symbol `q3` 的 value range 缺失来源。

- [#187721 [Inductor] Silent correctness : F.kl_div reduction over -0.0 yields different signbits in Eager vs Compiled](https://github.com/pytorch/pytorch/issues/187721)
  - 关注原因: 有 silent correctness 标签，但 maintainer 复现后认为可能是 Inductor 默认 numerics，而非 bug。
  - 建议动作: 明确该行为是否符合 Inductor numerics contract；若符合预期，建议 relabel/close 并补充说明。

## Issue 分析

### #187715 `torch.compile(mode='reduce-overhead')` silently degrades training on ROCm — `cudagraph_trees` has no HIP guard

- 链接: https://github.com/pytorch/pytorch/issues/187715
- 状态: open; 更新时间: 2026-06-20T01:51:38Z; 关键词: compile
- 标签: module: rocm, module: correctness (silent), module: cuda graphs, module: inductor
- 摘要: 作者报告 ROCm 上 `torch.compile(mode='reduce-overhead')` 相比 default/no-compile 训练 loss 收敛明显变慢，并怀疑 Inductor `cudagraph_trees.py` 缺少 HIP guard。
- 领域: Inductor
- 类型: bug
- 影响: high - silent training degradation 可能直接影响 ROCm 训练结果。
- 关键信号: 平台为 MI300X、ROCm 7.0、PyTorch 2.10；作者称 HIP Graph API 单独测试正常；评论关联 ROCm/clr#280；目前缺少 maintainer 复现确认。
- 建议跟进: 先在 ROCm 复现 `reduce-overhead` vs default/no-compile loss 曲线，再决定是否对 HIP 禁用或 guard `cudagraph_trees` 新实现。

### #187728 [vllm] [2.13 regression][Inductor] FxGraphCache._save_graph calls ShapeEnv.produce_guards_expression_with_source_info, missing on custom ShapeEnv

- 链接: https://github.com/pytorch/pytorch/issues/187728
- 状态: open; 更新时间: 2026-06-19T15:03:01Z; 关键词: inductor
- 标签: module: crash, module: bc-breaking, module: regression, module: inductor, module: vllm
- 摘要: vLLM standalone-compile 路径在 torch 2.13.0 因 custom `ShapeEnv` 缺少新方法而在 `FxGraphCache._save_graph` 崩溃。
- 领域: Inductor
- 类型: regression
- 影响: high - 下游 vLLM engine 初始化失败，且标记为 BC-breaking regression。
- 关键信号: 报错为 `AttributeError: 'AlwaysHitShapeEnv' object has no attribute 'produce_guards_expression_with_source_info'`；环境含 torch 2.13.0、Triton 3.7.1、CUDA 13.0、Python 3.12；无评论。
- 建议跟进: 检查 `FxGraphCache._save_graph` 是否可使用 feature detection/fallback，并补一条覆盖 custom `ShapeEnv` 的兼容测试。

### #187721 [Inductor] Silent correctness : F.kl_div reduction over -0.0 yields different signbits in Eager vs Compiled

- 链接: https://github.com/pytorch/pytorch/issues/187721
- 状态: open; 更新时间: 2026-06-19T17:24:18Z; 关键词: compile, inductor
- 标签: module: loss, module: half, module: correctness (silent), module: reductions, module: inductor
- 摘要: `F.kl_div(..., reduction='mean', log_target=True)` 在 fp16 下 Eager 返回 `+0.0`，compiled 返回 `-0.0`，下游 `copysign` 等 sign-sensitive op 可产生差异。
- 领域: Inductor
- 类型: unclear
- 影响: medium - 有 signbit 行为差异，但 maintainer 评论认为可能符合 Inductor 默认 numerics。
- 关键信号: repro 使用 `torch.compile(fn, backend="inductor", fullgraph=True)`；jansel 在 main 上复现 CPU/CUDA 差异，并认为 compiled 更接近 fp64 负 signbit，bug 证据偏弱。
- 建议跟进: 给出 numerics policy 判断；若符合预期，关闭或改为 docs/expected behavior。

### #187337 [inductor] model failed with torch._inductor.exc.InductorError: AssertionError: vr must not be None for symbol q3

- 标签: module: dynamic shapes, module: inductor
- 摘要: `benchmarks/dynamo/timm_models.py` 的 `jx_nest_base` training accuracy run 在 Inductor codegen/compile 阶段触发 dynamic shapes AssertionError。
- 领域: Inductor
- 类型: bug
- 影响: medium - 影响 benchmark/model compile 路径，但当前 evidence 主要是长 stack trace，缺少最小 repro。
- 关键信号: 命令包含 `--backend=inductor --training --float32 --only jx_nest_base`；stack trace 到 `torch/_inductor/compile_fx.py` 和 `graph.compile_to_module()`；评论提到 Intel XPU Triton CI 有同类问题。
- 建议跟进: 从 benchmark 输入抽取最小 FX graph，定位 `q3` symbol 的 value range 为什么为空。
