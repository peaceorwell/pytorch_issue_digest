## 今日概览

- 今日匹配 6 个 issue：3 个 open，3 个 closed。
- 主要风险信号是两个 open 的 high priority regression：Dynamo guard eval 性能退化，以及 Inductor CPU bounds-check codegen 修复不完整。
- 主题集中在 Dynamo guard/cache lookup 开销、Inductor CPU codegen、vLLM/ShapeEnv 兼容性、torch.compile memory optimization RFC。
- 未看到 silent correctness 证据；问题主要是性能退化、编译失败或 crash。
- #187728 已关闭且评论称由 PR #187581 修复，但仍值得关注 vLLM + 2.13 集成回归是否完全消除。

## 重点关注

- [#185886 [torch.compile] Clarification/regression: Dynamo cache lookup guard eval is much slower in 2.12 vs 2.7 after `inline_inbuilt_nn_modules` became always True](https://github.com/pytorch/pytorch/issues/185886)
  - 关注原因: high priority Dynamo performance regression；证据显示大模型 guard eval 从约 1 ms 增至 3-4 ms，维护者评论复现了随层数约 4x 更差的 scaling。

- [#187335 [Inductor][CPU] #180212 fix is incomplete — #178244 reproducer still fails identically on 2.12.0+cpu (workaround: assert_indirect_indexing=False)](https://github.com/pytorch/pytorch/issues/187335)
  - 关注原因: high priority Inductor CPU regression；用户报告 #180212 未修复原始 reproducer，2.12.0+cpu 仍在 generated CPP bounds-check 路径失败。
  - 建议动作: 用 nightly/2.13 验证维护者所称修复，补充 #178244 reproducer 的 CPU regression test，并确认 workaround 文档化或移除需要。

- [#187728 [vllm] [2.13 regression][Inductor] FxGraphCache._save_graph calls ShapeEnv.produce_guards_expression_with_source_info, missing on custom ShapeEnv](https://github.com/pytorch/pytorch/issues/187728)
  - 关注原因: closed regression，但影响 vLLM standalone compile engine init；评论称 PR #187581 已回退引入问题的 FX graph cache guard provenance change。
  - 建议动作: 确认 vLLM CI 对 torch 2.13/test channel 已恢复，并保留覆盖 custom ShapeEnv 的兼容性测试。

## Issue 分析

### #185886 [torch.compile] Clarification/regression: Dynamo cache lookup guard eval is much slower in 2.12 vs 2.7 after `inline_inbuilt_nn_modules` became always True

- 链接: https://github.com/pytorch/pytorch/issues/185886
- 状态: open; 更新时间: 2026-06-22T02:47:20Z; 关键词: compile, dynamo
- 标签: high priority, module: performance, module: regression, module: dynamo, module: guards
- 摘要: 大型 decoder-style inference workload 从 PyTorch 2.7 迁到 2.12 后，Dynamo cache lookup / guard eval 进入 compiled region 前的开销明显增加。
- 领域: Dynamo
- 类型: regression
- 影响: high，high priority 且影响推理 runtime overhead。
- 关键信号: 报告称 guard eval 约从 1 ms 增至 3-4 ms；评论称 synthetic model 复现，1 层接近 2.7，但随层数 scaling 约 4x 更差；热点包括 Python `LAMBDA_GUARD`、unspecialized symbolic floats、`not math.isnan(...)` guard。
- 建议跟进: 请求并纳入 synthetic repro，profile root guard tree 中 Python lambda guard 的成本，确认是否能恢复热点 guard 的 C++/specialized fast path。

### #187335 [Inductor][CPU] #180212 fix is incomplete — #178244 reproducer still fails identically on 2.12.0+cpu (workaround: assert_indirect_indexing=False)

- 链接: https://github.com/pytorch/pytorch/issues/187335
- 状态: open; 更新时间: 2026-06-21T19:36:39Z; 关键词: inductor
- 标签: high priority, module: cpu, module: regression, has workaround, module: inductor, module: sdpa
- 摘要: 用户报告 #180212 虽标记关闭 #178244，但原 reproducer 在 2.12.0+cpu 仍以相同 generated CPP 错误失败。
- 领域: Inductor
- 类型: regression
- 影响: high，CPU Inductor codegen regression 仍阻断 reproducer，且已有 high priority 标签。
- 关键信号: `assert_indirect_indexing=False` 可绕过；`TORCHINDUCTOR_DISABLE_CPP_BOUNDS_CHECK=1` 不可绕过；错误为 generated `main.cpp` 中 `tmp2` 未声明，位于 bounds-check `TORCH_CHECK` indexed load 路径；维护者建议试 nightly，并称应在 2.13 修复。
- 建议跟进: 在 nightly 和 2.13 branch 上重跑 #178244 reproducer，若已修复则补 regression test；若未修复，聚焦 CPP bounds-check 临时变量作用域/codegen。

### #187728 [vllm] [2.13 regression][Inductor] FxGraphCache._save_graph calls ShapeEnv.produce_guards_expression_with_source_info, missing on custom ShapeEnv

- 链接: https://github.com/pytorch/pytorch/issues/187728
- 状态: closed; 更新时间: 2026-06-21T16:20:09Z; 关键词: inductor
- 标签: module: crash, module: bc-breaking, module: regression, module: inductor, module: vllm
- 摘要: torch 2.13.0 test channel 中 Inductor `FxGraphCache._save_graph` 无条件调用新 ShapeEnv method，导致 vLLM custom `AlwaysHitShapeEnv` crash。
- 领域: Inductor
- 类型: regression
- 影响: medium，已关闭但曾阻断 vLLM standalone compile engine init。
- 关键信号: `AttributeError: 'AlwaysHitShapeEnv' object has no attribute 'produce_guards_expression_with_source_info'`；环境为 torch 2.13.0、Triton 3.7.1、CUDA 13.0、Python 3.12；评论称 PR #187581 已回退相关 change，并验证 legacy ShapeEnv save path 不再 crash。
- 建议跟进: 确认 vLLM 对应 CI/job 重新通过，并为 custom/subclassed ShapeEnv 的 FX graph cache save path 增加兼容性覆盖。

### #181243 Dynamo shouldn't assume modules are reimportable

- 链接: https://github.com/pytorch/pytorch/issues/181243
- 状态: closed; 更新时间: 2026-06-21T06:45:21Z; 关键词: dynamo
- 标签: module: dynamo
- 摘要: Dynamo tracing 通过 importlib 按路径加载且未注册到 `sys.modules` 的模块函数时，会尝试按模块名重新 import 并触发 `ModuleNotFoundError`。
- 领域: Dynamo
- 类型: bug
- 影响: low，issue 已关闭，但 JSON 未提供修复或关闭依据。
- 关键信号: repro 使用 `importlib.util.spec_from_file_location` 加载临时模块且不写入 `sys.modules`；`torch.compile(fn)` 触发 Dynamo `LOAD_GLOBAL` resolution 中的 re-import；实际错误为 `InternalTorchDynamoError` wrapping `ModuleNotFoundError`。
- 建议跟进: 确认关闭对应的修复/测试是否存在；若没有，至少保证错误信息清晰或对非 reimportable module 做 fallback。
