# PyTorch Compiler Issue Digest - 2026-05-30

## 今日概览

- 今日匹配到标题含 `compile`/`inductor`/`dynamo` 的 issue 共 22 条，其中 open 13 条、closed 9 条。
- 今日最强风险信号是 Inductor 数值正确性集中出现：`signed zero`、`bfloat16`、type promotion 与梯度一致性均有 open 报告，且多条带 `module: correctness (silent)`。
- 主要主题集中在 4 类：Inductor 数值边界行为、dynamic shapes/SymInt 崩溃、`torch.compile` 与 CUDA graphs/stream 同步语义、以及若干已关闭的历史回归/优化项。
- 高优先/静默正确性项存在：open 中 4 条有 `module: correctness (silent)` 标签；另有 1 条标题含 `silent incorrectness` 但最新评论显示复现证据偏弱。

## 重点关注

1. [#185696 [Inductor] torch.atan2 yields incorrect result for x=0.0 with float16 on CUDA (loses signed zero)](https://github.com/pytorch/pytorch/issues/185696)  
   关注原因：`torch.atan2(x, -x)` 在 `x=0.0` 时 compiled 与 eager 出现 `pi -> 0` 级别偏差，属于静默正确性。  
   建议动作：优先复现并在 Inductor/Triton 增加 signed-zero 回归测试（bit-level 断言）。

2. [#185605 [Inductor][CUDA][bf16] torch.add with a 0-dim float64 scalar returns nonzero where eager returns zero](https://github.com/pytorch/pytorch/issues/185605)  
   关注原因：bf16 + 0-d float64 出现“应为 0 却非 0”的结果，疑似 type promotion 路径错误，且已有人在做 PR。  
   建议动作：跟进提交中的 cast/promotion 修复并补齐 0-d scalar 组合测试矩阵。

3. [#185610 [Inductor] Correctness discrepancy in torch.minimum with signed zeros (-0.0 vs 0.0) on CUDA (bfloat16)](https://github.com/pytorch/pytorch/issues/185610)  
   关注原因：`-0.0` 符号位丢失，属于边界数值语义偏差，可能影响依赖 IEEE 语义的模型。  
   建议动作：定位 `minimum` lowering 的符号保持逻辑，并加入 `bfloat16/fp16` signed-zero 覆盖。

4. [#185596 [Inductor] Correctness mismatch in torch.cumulative_trapezoid with bfloat16](https://github.com/pytorch/pytorch/issues/185596)  
   关注原因：前向与反向均不一致，`grad_x` 最大差约 0.378，影响训练稳定性。  
   建议动作：先最小化到单算子 backward 路径，再对 derivative/decomposition 分支做逐步对比。

5. [#185546 `torch.compile(mode='reduce-overhead')` fails when user model uses wait_stream to synchronize side work](https://github.com/pytorch/pytorch/issues/185546)  
   关注原因：用户显式 `wait_stream` 仍触发 `cudaErrorStreamCaptureUnjoined`，说明 reduce-overhead 与 stream/capture 语义存在缺口。  
   建议动作：复现后在 reduce-overhead 路径补充 side-stream 依赖建模与回归用例。

6. [#185630 [PT2] RuntimeError with garbage shape in apply_view_meta_sequence when using torch.compile(dynamic=True)](https://github.com/pytorch/pytorch/issues/185630)  
   关注原因：AOTAutograd alias/view 元数据阶段出现“垃圾 shape”崩溃，dynamic=True 下稳定性风险高。  
   建议动作：向报告者索要最小化 repro（含 `TORCH_LOGS`/minifier 输出），优先定位 `apply_view_meta_sequence` 输入约束。

- 建议跟进: 在 derivatives/decomposition 分支做逐层数值核对，并补 bf16 gradcheck 回归。
