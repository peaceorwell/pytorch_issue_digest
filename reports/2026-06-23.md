# PyTorch Compiler Issue Digest - 2026-06-23

## 今日概览

- 今日匹配标题关键词的 Issue 共 15 个：open 10 个，closed 5 个。
- 主要风险信号集中在 Inductor correctness/regression：`torch.nextafter` silent correctness、ROCm `reduce-overhead` 训练退化、vLLM 2.13 FP8 matmul regression。
- 主题包括 Dynamo guard eval 性能回退、Inductor dynamic shapes/FakeTensor 失败、平台相关问题（ROCm、MPS、Windows、CPU）、以及 fx wrapper/compile UX feature request。
- 有 5 个带 `high priority`，3 个带 `module: correctness (silent)`；其中 #187340 和 #187715 最值得优先确认。

## 重点关注

- [#187340 [torch.compile][Inductor][CUDA] torch.nextafter is incorrectly compiled as no-op for non-contiguous float16 tensors](https://github.com/pytorch/pytorch/issues/187340)
  - 关注原因: high priority + silent correctness；compiled 输出被报告为与输入 bit pattern 相同，影响非连续 fp16 CUDA tensor。
  - 建议动作: 用 nightly/main 复现并最小化到 Inductor codegen/layout 处理，补 correctness test。

- [#187715 `torch.compile(mode='reduce-overhead')` silently degrades training on ROCm — `cudagraph_trees` has no HIP guard](https://github.com/pytorch/pytorch/issues/187715)
  - 关注原因: silent training degradation，ROCm MI300X/ROCm 7.0/PyTorch 2.10；证据指向 `cudagraph_trees.py` 缺 HIP guard，但目前评论证据较少。
  - 建议动作: 在 ROCm 上独立复现 loss 曲线，并确认是否应禁用/分流 CUDA graphs trees 路径。

- [#187484 [vllm] [2.13 regression][Inductor] backend='inductor' raised bare AssertionError compiling w8a8 block-fp8 matmul](https://github.com/pytorch/pytorch/issues/187484)
  - 关注原因: high priority release regression，影响 vLLM H100 FP8 matmul/FusedMoE 测试；评论已 bisect 到 #184193，建议 revert。
  - 建议动作: 跟进 #187581 revert/cherry-pick 状态，并确认 2.13 release branch 上 vLLM 测试恢复。

- [#185886 [torch.compile] Clarification/regression: Dynamo cache lookup guard eval is much slower in 2.12 vs 2.7 after `inline_inbuilt_nn_modules` became always True](https://github.com/pytorch/pytorch/issues/185886)
  - 关注原因: high priority performance regression；报告称大模型 guard eval/cache lookup 从约 1ms 增至 3-4ms，评论指出 Python `LAMBDA_GUARD` 扩大。
  - 建议动作: 评估 #187868，并用 synthetic/真实 decoder workload 验证 guard eval scaling。

- [#187415 [Inductor] torch.compile fails on CUDA with bool mask indexing after torch.eye constructor movement: AssertionError in _rename_unbacked_to](https://github.com/pytorch/pytorch/issues/187415)
  - 关注原因: high priority dynamic shapes crash，涉及 constructor movement、FakeTensor、unbacked SymInt rebinding。
  - 建议动作: 添加 bool mask indexing + `torch.eye(dtype=bool)` CUDA repro 到动态 shape/Inductor 测试，定位 `FakeTensorUpdater.incremental_update()`。

- [#187335 [Inductor][CPU] #180212 fix is incomplete — #178244 reproducer still fails identically on 2.12.0+cpu (workaround: assert_indirect_indexing=False)](https://github.com/pytorch/pytorch/issues/187335)
  - 关注原因: high priority CPU regression，已知 workaround；评论称可能在 2.13 修复但仍需验证。
  - 建议动作: 请报告者/maintainer 用 nightly CPU 复现矩阵确认，并补回 #178244 原始 repro 覆盖。

### #178265 [Dynamo] Unable to trace RemovableHandle when register_forward_hook is called conditionally in forward method

- 摘要: 在 `forward` 内条件注册 forward hook 时，Dynamo 无法表示 `RemovableHandle`，导致 `torch.compile(fullgraph=True)` 失败。

- 建议跟进: 若未有文档说明，补充 `torch.compile` 对动态 hook 注册的限制说明或诊断信息。

### #185886 [torch.compile] Clarification/regression: Dynamo cache lookup guard eval is much slower in 2.12 vs 2.7 after `inline_inbuilt_nn_modules` became always True

- 链接: https://github.com/pytorch/pytorch/issues/185886

- 摘要: 大型 inference workload 从 2.7 到 2.12 后 Dynamo guard eval/cache lookup 开销明显上升。
- 领域: Dynamo
- 类型: performance

- 关键信号: 报告称约 1ms 增至 3-4ms；评论指出 C++ guard 变为 Python `LAMBDA_GUARD`，并链接 PR #187868。
- 建议跟进: review/benchmark #187868，确认 float module attrs、object aliasing guards 的成本是否可回退到更快路径。
