# PyTorch Compiler Issue Digest - 2026-06-11

## 今日概览

- 今日按标题关键词匹配到 17 个 issues：11 个 open，6 个 closed。
- 主要风险信号集中在 silent correctness / numerics：`torch.compile` wrong gradient、Flex Attention NaN、CPU bf16/fp16 `fmod/remainder` 与 eager 不一致，以及 FakeTensorUpdater 的潜在 silent incorrectness。
- 主题分布包括 Inductor lowering / dynamic shapes / unbacked symbols、Dynamo guard 性能回退、Triton/complex/FP8 codegen 覆盖缺口。
- 有明确 high-priority 标签的 open issues：#164920、#185886；另有 #186799、#186775、#186875 值得 correctness 优先排查。

## 重点关注

- [#186799 `torch.compile` silently produces wrong gradient for `atan2(x, y).amin(dim)` on float32](https://github.com/pytorch/pytorch/issues/186799)  
  关注原因: Inductor backend 产生 silent wrong gradient，`aot_eager` 正确，属于高风险 correctness。  
  建议动作: 加入最小回归测试，并定位 `atan2 -> amin/amax` backward lowering 或 reduction grad 分发逻辑。

- [#186775 Flex Attention produces NaN with `torch.compile(flex_attention, dynamic=True)` and batch-dependent mask closures](https://github.com/pytorch/pytorch/issues/186775)  
  关注原因: 训练中出现 NaN，标签为 `module: correctness (silent)`，但目前仍缺最小复现。  
  建议动作: 用提交的 batch data 复现，并优先隔离 batch-dependent BlockMask partial-block Triton 路径。

- [#164920 Investigate _inductor_lowering_function tag in FakeTensorUpdater](https://github.com/pytorch/pytorch/issues/164920)  
  关注原因: high priority，报告明确提到 FakeTensorUpdater 可能无法正确更新 `_inductor_lowering_function` 节点，并可能导致 silent incorrectness。  
  建议动作: 审计进入 FakeTensorUpdater 的 callable node 类型，增加 invariant check 或明确 fallback/skip 机制。

- [#185886 [torch.compile] Clarification/regression: Dynamo cache lookup guard eval is much slower in 2.12 vs 2.7 after `inline_inbuilt_nn_modules` became always True](https://github.com/pytorch/pytorch/issues/185886)  
  关注原因: high priority performance regression，大模型 inference guard/cache lookup 从约 1 ms 增至 3-4 ms。  
  建议动作: 让报告方验证建议的 guard 配置，并进一步 profile object aliasing guard 与 C++ symbolic shape guard 路径。

- [#186875 [Inductor] fmod/remainder with Python float scalar diverge from eager for bf16/fp16 on CPU (same class as #185517)](https://github.com/pytorch/pytorch/issues/186875)  
  关注原因: CPU bf16/fp16 数值差异可达到一个 modulus，不只是 epsilon。  
  建议动作: 按报告建议为 `aten.fmod` / `aten.remainder` 启用 scalar rounding，并补回归测试。
