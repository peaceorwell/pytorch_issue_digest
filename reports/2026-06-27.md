# PyTorch Compiler Issue Digest - 2026-06-27

## 今日概览

- 今日匹配 11 个 issue：open 8 个，closed 3 个。
- 主要风险信号是 Inductor 相关 CI/accuracy 回归：A10G cuDNN 9.23.1 后持续红、XPU AMP fp16 存在 silent correctness 回归、TPU/Pallas 构建被 `torch.cholesky` 移除影响。
- 主题集中在 Inductor CI 稳定性、CUDA graphs 输出回灌、`torch.compile` 重编译/Autotune crash、Dynamo hotpath 性能。
- 有高优先级与 silent-correctness 项：#188261、#187951、#187335；其中 #188261 仍 open。

## 重点关注

- [#188261 [inductor][XPU] PR #184366 causes AMP fp16 training accuracy regression on XPU](https://github.com/pytorch/pytorch/issues/188261)
  - 关注原因: open 的 silent correctness/accuracy regression，已 bisect 到 #184366，影响 XPU AMP fp16 training 的 BatchNorm gradient。
  - 建议动作: 优先由 Inductor/XPU owner 复核 `joint_graph.py` dtype convert 保留逻辑，确认 revert 或精细化 guard。

- [#188288 inductor / test-osdc (timm, torchbench) a10g jobs red since cuDNN 9.23.1 upgrade (#187091) — eager non-determinism on conv/BatchNorm models](https://github.com/pytorch/pytorch/issues/188288)
  - 关注原因: A10G 上 Inductor accuracy jobs 自 2026-06-13 持续红；证据指向 eager/cuDNN 非确定性，但会阻塞 Inductor CI 信号。
  - 建议动作: 跟进已转给 cuDNN 的 slim repro，并推进临时 errata/filter PR 让 CI 恢复有效信号。

- [#188290 inductor-pallas-tpu build broken by torch.cholesky removal (#186817): torch_tpu includes removed ATen/ops/cholesky_ops.h](https://github.com/pytorch/pytorch/issues/188290)
  - 关注原因: `inductor-pallas-tpu` 在 build 阶段失败，`torch_tpu` 仍 include 已删除的 `ATen/ops/cholesky_ops.h`。
  - 建议动作: 在 out-of-tree `torch_tpu` 迁移 autocast policy 到 `linalg.cholesky`，并更新 pinned dependency。

- [#188069 torch.compile(mode="max-autotune") crashes with too many positional arguments during bmm autotuning when template inputs are deduplicated](https://github.com/pytorch/pytorch/issues/188069)
  - 关注原因: `max-autotune`/Triton template cache 在 dedup input 后参数数量不一致导致 crash；已有 #188268。
  - 建议动作: Review #188268，重点验证 cross-compilation cached kernel 的 signature 参数计数。

### #188288 inductor / test-osdc (timm, torchbench) a10g jobs red since cuDNN 9.23.1 upgrade (#187091) — eager non-determinism on conv/BatchNorm models

- 链接: https://github.com/pytorch/pytorch/issues/188288
- 状态: open; 更新时间: 2026-06-27T00:29:01Z; 关键词: inductor
- 标签: 无
- 摘要: A10G 上 Inductor accuracy jobs 持续红，但正文强调失败发生在 eager baseline 两次运行不一致，未证明是 Inductor regression。
- 领域: Inductor
- 类型: flaky test
- 影响: high，持续污染 Inductor CI，且涉及 timm/torchbench 多个 conv+BatchNorm 模型。
- 关键信号: cuDNN 9.23.1.3 升级后出现；`eager_two_runs_differ`、`EAGER_FAILED`；eqy 已能用 end-to-end model repro，并转给 cuDNN。
- 建议跟进: 跟踪 cuDNN engine errata/filter，并把 #187951 合并到同一条 CI 恢复路径管理。

### #188218 [inductor] `LoweringException: AssertionError: max not supported for zero-dimension tensors!`

- 链接: https://github.com/pytorch/pytorch/issues/188218
- 状态: open; 更新时间: 2026-06-26T23:47:08Z; 关键词: inductor
- 标签: module: crash, module: pooling, module: inductor
- 摘要: `torch.compile(backend="inductor")` 在 pooling/zero-dimension tensor lowering 路径 crash，而 eager forward 可返回结果。
- 领域: Inductor
- 类型: bug
- 影响: medium，存在最小 repro，但 `FractionalMaxPool2d` 的 zero/negative kernel_size 语义本身也不清晰。
- 关键信号: repro 涉及 `AdaptiveMaxPool2d`、`FractionalMaxPool2d(0)`、`ZeroPad2d`；评论指出 eager forward、CPU backward、CUDA backward 行为不一致。
- 建议跟进: 先由 pooling/operator owner 明确 non-positive kernel_size 是否合法，再决定 Inductor lowering 是支持还是显式报错。

### #188077 torch._dynamo.disable seems expensive

- 状态: open; 更新时间: 2026-06-26T14:23:21Z; 关键词: dynamo
- 标签: module: performance, module: dynamo
- 摘要: `torch._dynamo.disable` 在 custom operator hotpath 上增加约 300-500ns overhead。
- 领域: Dynamo
- 类型: performance
- 影响: medium，单次开销小但位于 custom op hotpath，可能在高频调用中放大。
- 关键信号: 评论中 cleanup 将 noop per-call 从约 230ns 降到 105ns；zou3519 建议 custom_op 内联 disable/reenable eval frame。
- 建议跟进: 评估 `DisableContext._fn` export-only 工作拆分，并为 `torch.library.custom_op` 设计更薄的 eval-frame guard。

### #187953 torch.compile: out= variants of CompositeImplicitAutograd linalg ops (linalg.norm, cholesky, ...) recompile on every input shape

- 链接: https://github.com/pytorch/pytorch/issues/187953
- 状态: open; 更新时间: 2026-06-26T14:00:33Z; 关键词: compile
- 标签: module: linear algebra, module: fakeTensor, module: dynamic shapes, module: guards, module: compile-time, module: pt2-dispatcher
- 摘要: CompositeImplicitAutograd linalg `out=` variants 在新 shape 下反复 recompile，functional variants 不受影响。
- 领域: torch.compile
- 类型: performance
- 影响: medium，可能覆盖 `linalg.norm`、`cholesky`、`qr`、`eig`、`svd` 等多个 linalg out kernel。
- 关键信号: 根因被定位到 C++ `out=` kernel 的 `resize_output` check 在 FakeTensor propagation 中添加 specializing guard；评论称 Python decomposition 和 naive `sym_sizes()` 都不足。
- 建议跟进: 在 dispatcher/meta 或 C++ out kernel resize check 处修复 symbolic size guard，而非只改 Python decomposition。
