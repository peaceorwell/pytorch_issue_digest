# PyTorch Compiler Issue Digest - 2026-06-12

## 今日概览

- 今日匹配 22 个标题含 `compile` / `inductor` / `dynamo` 的 issue：open 11，closed 11。
- 主要风险信号是 open 的 FlexAttention NaN 静默正确性问题和 Dynamo guard/cache lookup 性能回退。
- 主题集中在 Inductor dynamic shapes / FlexAttention、Dynamo guards、distributed + `torch.compile`、AOTInductor/XPU 测试禁用，以及若干 Inductor CPU/CUDA correctness/crash 回归。
- 高优先级或静默正确性项存在：#185886、#186775 仍 open；#185806、#183767 已 closed 但建议确认回归测试覆盖。

## 重点关注

1. [#186775 Flex Attention produces NaN with `torch.compile(flex_attention, dynamic=True)` and batch-dependent mask closures](https://github.com/pytorch/pytorch/issues/186775)  
   关注原因: open 且标记 `module: correctness (silent)`，bf16 + batch-dependent BlockMask 下出现 NaN；证据还缺最小 repro。  
   建议动作: 用作者提供的 batch 数据在目标 GPU 上复现，优先缩小到 partial-block Triton kernel / BlockMask codegen 差异。

2. [#185886 [torch.compile] Clarification/regression: Dynamo cache lookup guard eval is much slower in 2.12 vs 2.7 after `inline_inbuilt_nn_modules` became always True](https://github.com/pytorch/pytorch/issues/185886)  
   关注原因: open、`high priority`、`module: regression`，大型推理 workload 的 guard/cache lookup 从约 1 ms 升到 3-4 ms，候选配置未改善。  
   建议动作: 分析 guard tree 和 cache lookup profile，围绕 `inline_inbuilt_nn_modules`、object aliasing guard、symbolic shape guard 做定向 bisect。

3. [#187073 torch.compile recompiles when input alternates between AsyncCollectiveTensor and Tensor](https://github.com/pytorch/pytorch/issues/187073)  
   关注原因: FSDP + TP 场景下 ACT 与 resolved Tensor 切换触发 recompilation，可能迫使用户调高 Dynamo cache limit。  
   建议动作: 等 #186442 后只放宽 ACT-traced -> Tensor-runtime 方向的 class guard，并加 distributed regression test。

4. [#183833 [Inductor][HOP] FlexAttention should bind derived unbacked tensor input extents from runtime metadata](https://github.com/pytorch/pytorch/issues/183833)  
   关注原因: open，H100 repro agent 已确认 FlexAttention backward 因 data-dependent symbolic guard 失败。  
   建议动作: 在 Inductor/FlexAttention 边界绑定 derived unbacked extents，并避免对保守 fallback 路径强行生成数据依赖 guard。

5. [#185806 [Inductor][AOTI] codegen_symbol uses float reciprocal for integer dim recovery, silently corrupts dynamic batches when 1/K is not exactly representable in IEEE-754](https://github.com/pytorch/pytorch/issues/185806)  
   关注原因: 已 closed 但同时是 `high priority` 和静默正确性问题，涉及 AOTI dynamic batch 维度恢复错误。  
   建议动作: 确认修复包含非 2 的幂 `K`、`bs=1`、attention 路径的回归测试。
