# PyTorch Compiler Issue Digest - 2026-06-16

## 今日概览

- 共 25 个标题匹配 issue：open 16，closed 9。
- 今日主要风险信号是 silent correctness：forward-mode AD tangent 丢失、custom op cache 误复用、special/nextafter 数值不一致等。
- 主题集中在 Inductor codegen、dynamic shapes/reductions、CPU C++ bounds check、special functions 数值边界、Dynamo/export/benchmark 支持。
- 有 high-priority 项：#187284、#187319、#187335；另有多个未标 high priority 但看起来值得尽快确认的 correctness 回归。
- 若证据较弱，主要是 #186775：报告了 Flex Attention NaN，但仍标记 needs reproduction。

## 重点关注

- [#187284 `torch.compile` with `inductor` backend silently drops forward-mode AD tangents (returns `None`)](https://github.com/pytorch/pytorch/issues/187284)
  - 关注原因: high priority + silent correctness；Inductor 下 forward-mode AD tangent 变成 `None`，还影响 Hessian。
  - 建议动作: 先决定 unsupported 时是否 hard error，再补 forward AD + `torch.compile(backend="inductor")` 回归测试。

- [#187319 torch.compile FX graph does not distinguish custom ops with the same name but different mutates_args](https://github.com/pytorch/pytorch/issues/187319)
  - 关注原因: high priority；`mutates_args` 不进入 FX/cache 区分，可能复用错误 Inductor cache 并静默删掉 mutation op。
  - 建议动作: 把 schema/mutation metadata 纳入 cache key 或 graph identity，并覆盖跨进程 cache 复用测试。

- [#187335 [Inductor][CPU] #180212 fix is incomplete — #178244 reproducer still fails identically on 2.12.0+cpu (workaround: assert_indirect_indexing=False)](https://github.com/pytorch/pytorch/issues/187335)
  - 关注原因: high priority regression；声称 #180212 未修复原 CPU SDPA/closure mask C++ codegen 失败。
  - 建议动作: 用 #178244 原 repro 在 2.12/main 复验，修 bounds-check 临时变量声明顺序，并避免仅关闭旧 issue。

- [#187407 [inductor] TypeVar(default=) breaks Python 3.11: torch._inductor fails to import on Python < 3.13 (regression in 2.10.0)](https://github.com/pytorch/pytorch/issues/187407)
  - 关注原因: Inductor import 级 regression；如果属实会让 Python 3.11 上 `torch._inductor` 不可用。
  - 建议动作: 在 Python 3.11 CI/nightly 上复现，移除或兼容 `TypeVar(default=...)`，评估 2.10.x backport。

- [#187340 [torch.compile][Inductor][CUDA] torch.nextafter is incorrectly compiled as no-op for non-contiguous float16 tensors](https://github.com/pytorch/pytorch/issues/187340)
  - 关注原因: 未标 priority 但有明确 eager/compiled bit-pattern mismatch；`nextafter` 对非连续 fp16 近似 no-op。
  - 建议动作: 最小化到 Inductor lowering/kernel，补 non-contiguous fp16 CUDA correctness 测试。

- [#187336 [Inductor] torch.compile loses signbit in torch.special.log_ndtr, causing discrepancies in sign-sensitive ops (e.g., copysign, atan2)](https://github.com/pytorch/pytorch/issues/187336)
  - 关注原因: silent correctness；`-0.0` 变 `+0.0`，下游 `copysign`/`atan2` 可见。
  - 建议动作: 检查 `log_ndtr` decomposition/lowering 是否保留 signed zero，增加 signbit-sensitive 测试。
