# PyTorch Compiler Issue Digest - 2026-05-25

## 今日概览

- 今日命中 `compile/inductor/dynamo`（标题匹配）共 **17** 条，`open` **7**、`closed` **10**。  
- 主要风险信号是 **编译期与运行时语义不一致**：包括异常类型包装、AOTAutograd 类型协商、以及 CUDA graph capture 下的编译行为。  
- 值得关注的主题包括：`torch.compile` 回归与兼容性（VRAM、`axis=`/`options` 参数）、Inductor 与 Triton/worker 进程交互、DTensor/AOTAutograd 分布式路径稳定性。  
- 存在高优先级或潜在 silent-correctness 信号：#175058（`high priority`）与 #185074（`module: correctness (silent)`）。  
- 若按证据强度评估，部分问题已“看似修复但仍 open”，需要维护者做状态收敛与回归确认。  

## 重点关注

- **#185074 [\[RFC\] torch.compile + CUDA graph capture: Inductor JIT has no capture-state awareness, causes CPU→GPU copy error on first call](https://github.com/pytorch/pytorch/issues/185074)**  
  - 关注原因: 涉及 `module: correctness (silent)`，且在 ROCm 路径报告了“可能静默错误”，风险高于普通 crash。  
  - 建议动作: 先确定最小安全策略（capture 中禁编译或强制 fallback eager），再补跨 CUDA/ROCm 回归测试。  

- **#184643 [Inductor compile-worker subprocess+fork pool initializes CUDA in parent before fork, breaking with upstream Triton 3.7.0+](https://github.com/pytorch/pytorch/issues/184643)**  
  - 关注原因: 默认 worker/fork 机制与 upstream Triton 3.7+ 交互失效，影响面可能扩展到“安装 upstream triton wheel”的用户群。  
  - 建议动作: 明确 owner 后推进最小修复（避免 parent pre-fork CUDA init），并加 compile-worker 回归用例。  

- **#175058 [torch.compile VRAM usage regression between 2.9.1 and 2.10.0](https://github.com/pytorch/pytorch/issues/175058)**  
  - 关注原因: 带 `high priority`，且是版本回归+资源成本问题，容易影响生产升级决策。  
  - 建议动作: 以版本矩阵（2.9/2.10/2.11/nightly）复核修复覆盖范围，并在 issue 中补清晰“已修版本/未修版本”结论。  

- **#184980 [[torch.compile] AOTAutograd fails to coerce plain Tensor tangent for expected AsyncCollectiveTensor](https://github.com/pytorch/pytorch/issues/184980)**  
  - 关注原因: 分布式 + AOTAutograd + backward 路径，错误点明确但影响训练主路径，且当前仅有 workaround 信号。  
  - 建议动作: 先确认期望 coercion 方向与 API contract，再给出最小修复 PR 或明确 design 限制。
